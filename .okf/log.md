# Log

## 2026-11-17

* **A face it cannot draw is refused, not blank**: `outline()` on a face with no `glyf`, `CFF ` or `CFF2` (Apple's `hvgl` in PingFangUI, bitmap-only faces) is `TYPOG_NO_OUTLINES` (new, 10), where it gave an empty outline; the CFF2 refusal no longer says TrueType only. `describe()` adds each face's outline table as a seventh value. 6 breaks, each caught. [face](api/face.md).
* **CFF outlines** (`src/cff.c`): a face with `CFF ` and no `glyf` gives its Type 2 charstrings as cubic `'C'` steps, name-keyed and CID-keyed (FDSelect formats 0 and 3), by the rules in [face](api/face.md); CFF2 is still `TYPOG_CFF`. 66 CFF Pest tests write their own tables (`tests/Support/TinyCff.php`); 25 breaks of `cff.c`, each caught; they pass under guard malloc. Validated against FreeType (`FT_LOAD_NO_SCALE | FT_LOAD_NO_HINTING`) on every glyph of 25 Mac faces (Hiragino Sans W3 ×4, Hiragino Mincho ProN, Apple SD Gothic Neo ×18, Noto Sans Javanese, LastResort): 438,011 glyphs, identical, none refused. `cff.c` alone reads an outline in about 1 µs (Hiragino Sans W3); `outline()` takes about 6 µs with its PHP arrays.
* **Variable fonts**: `TypogFace` takes `$variations` and reads the face at that instance: `fvar`, `avar`, `gvar` (shared and private tuples, intermediate regions, point numbers, packed deltas, IUP, phantom points, composites), `HVAR`, `MVAR`. `vertical()` returns floats; `describe()` adds each face's axes. A malformed `fvar` instance size or a delta run crossing from x into y is `TYPOG_MALFORMED`. 66 Pest tests; 58 breaks of the variation code, each caught. Validated against HarfBuzz 15.1.0 on SF-Pro, SFNS and Skia at 7 instances: advances identical to its own reader, vertical metrics identical, outline extents within 1 unit. [face](api/face.md).

## 2026-11-16

* Bundle created with ext-typog 0.11.0: [face](api/face.md) (`TypogFace`, `TypogException`, 11 constants), [build](runbooks/build.md). `PHP_TYPOG_VERSION` 0.11.0, `branch-alias` `dev-main` is `0.11.x-dev`, on the Venusian 0.11 line. Built with `-Wall -Wextra` with no warning from `src/`; 20 Pest tests, each part of the reader broken once and watched fail (25 changes, all caught); the suite passes under guard malloc. Validated against Lustrous's PHP face, shaper and catalog description on the 1,333 faces of 745 files on a Mac: identical metrics, character maps, advances, outlines, CFF refusals, shaping and descriptions. Describing 456 files takes 14 ms (the PHP description 100 ms).
* **A collection's face count is bounded by its file**: a `ttcf` header claiming more than size / 32 faces (FreeType's bound: a 4-byte offset, a 12-byte header and one 16-byte table record per face) is `TYPOG_NOT_A_FONT`, in `describe()` and in the constructor. Fuzzing found it: one corrupted byte claimed billions of faces and `describe()` opened each in turn, for as long as the run was left. Fuzzing with randomly corrupted real fonts now finishes with no crash: 400 under guard malloc in 10 s, 3,000 in 9 s. Lustrous's PHP reader got the same bound.
